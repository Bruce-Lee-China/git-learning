# 台风实况与预警网站项目计划书

## 项目目标

为中国大陆沿海居民提供手机优先的台风查询网站，让居民快速查到所选市县的官方预警、正在监测的台风位置和移动趋势。首期选择一个沿海地市及其区县试点，具体地区以官方数据接入条件确定。

## 首期功能

| 页面 | 内容与交互 |
| --- | --- |
| 首页 | 手动选择市县并记住选择。置顶展示当地有效台风预警，下方列出正在监测的台风，支持多个台风并存。 |
| 台风详情 | 显示名称、编号、最新观测时刻、中心经纬度、移动方向和速度、中心附近最大风力及风速。方向或速度缺失时显示“暂无数据”。 |
| 路径地图 | 标出当前中心位置，使用实线展示历史路径、虚线展示官方预报路径，并显示预报点的预计时刻。提供文字列表供弱网和读屏用户查询。 |
| 预警详情 | 按所选行政区展示预警级别、适用区域、发布单位、发布时间、防御指引、状态及官方原文入口。 |

## 数据与预警

- 台风实况及预报优先对接中央气象台或获授权的气象数据服务。地方预警接入试点气象部门或获授权的预警渠道。上线前确认接口、转载条件、覆盖地区、更新频率和限流。官方参考入口为[中央气象台](https://www.nmc.cn/)和[国家预警信息发布中心](https://www.12379.cn/)。
- 支持蓝、黄、橙、红及地方规则中的其他级别，例如广东白色信号。界面同时标注颜色和文字，保留官方级别与防御指引。预警级别由官方报文提供，中心风力字段仅用于展示台风强度。依据[中国气象局管理办法](https://www.cma.gov.cn/zfxxgk/gknr/flfgbz/gz/202005/P020220628619411458474.pdf)及[广东地方规定](https://www.sz.gov.cn/cn/xxgk/zfxxgj/zcfg/content/post_8967088.html)。
- 按官方报文关联发布、更新和解除事件。明确区分“暂无有效预警”“预警数据暂不可用”和“数据更新延迟”。只有在数据源响应正常且明确无有效记录时，才显示“暂无有效预警”。
- 所有实况标注观测时刻，预警标注发布时间，页面标注最近同步时间，统一显示北京时间。超过按来源约定配置的时效阈值后，显示延迟提示、最近成功同步时间和官方查询入口。测试数据限定在标有“演示数据”的测试环境。

## 实现方案

使用响应式前端、后端查询接口和定时同步任务。后端统一台风编号、行政区代码和时间格式，保存原始报文与解析结果以便追溯。预警按来源标识及版本去重，乱序或重复同步时保留最新有效状态。对外提供台风列表、指定台风路径和指定行政区预警三个查询接口。地图采用具备合规授权的底图服务，台风和预警的文字视图独立加载。

## 里程碑

| 阶段 | 交付 |
| --- | --- |
| 第 1 周 | 确认试点和数据授权，收集实况及预警样本，完成手机端原型和接口字段表。 |
| 第 2 周 | 完成数据同步与查询接口，联通台风卡片和区县预警。 |
| 第 3 周 | 完成地图、状态提示及移动端适配，用历史报文演练升级、解除和数据中断。 |
| 第 4 周 | 接通试点正式数据，对照官方页面核验，设置同步监控并发布试点版。 |

排期按四周估算。第一周确认正式数据源能否接通，接入时间影响试点上线日期。

## 验收标准

- 在手机端可从首页查看所选区县的预警，并在点开台风详情后看到名称、位置、移动方向、移动速度和最大风力。
- 使用官方样本逐项核对预警的级别、区域、发布单位、时间和防御指引。升级后展示新版本，解除后退出有效预警列表。
- 同时回放两场台风，验证台风轨迹、观测时间和预报时间对应正确。禁用地图时，文字视图仍可完成查询。
- 模拟数据超时、重复及乱序报文，验证延迟状态、预警更新和解除符合预期。按照数据协议设置同步周期，并在试点部署中监控最近成功同步时间。

## 浙江省水利厅数据版

使用 Node.js 22 执行 `node scripts/sync.mjs`，然后打开 `dist/index.html`。页面内嵌本次抓取的快照，可直接打开。根目录的 `index.html` 是构建模板。实况和路径取自[浙江省水利厅](https://typhoon.slt.zj.gov.cn/)。当前无活跃台风时会展示最近结束的历史路径，并标明历史状态。地区预警通过页面中的官方入口查询。

首次部署时，在目标 GitHub 仓库的 Settings → Pages → Source 选择 GitHub Actions，并运行 **Sync Zhejiang typhoons and deploy Pages**。工作流在 master 分支变化时运行，也可手动触发，每小时第 7、22、37、52 分钟计划抓取并发布。GitHub 高负载时调度可能延迟。抓取失败会终止新部署，已发布快照会在超过 45 分钟后提示更新延迟。
